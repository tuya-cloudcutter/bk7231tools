# BK7258 serial download support

BK7258 uses the Beken HCI-style serial download protocol already implemented by
`bk7231tools`. Select the BK7258 profile explicitly because its register map and
flash size differ from the older BK7231 devices:

```sh
bk7231tools chip_info \
    --device /dev/ttyUSB0 \
    --chip bk7258 \
    --reset-mode rts
```

The BK7258 profile uses 460800 baud and an RTS-only reset unless the respective
options are given. The initial link check is always sent at 115200 baud. The
RTS sequence asserts the line for 0.1 seconds by default and does not change
DTR. Use `--reset-hold` to change the assertion time.

## Reading flash

The T5AI Core V1.0.1 used for validation returned JEDEC ID `c8 65 17`, whose
capacity field reports 8 MiB. The tool reads the JEDEC ID and uses its reported
capacity. Omit `--length` to read the entire detected flash without modifying
the device:

```sh
bk7231tools read_flash \
    --device /dev/ttyUSB0 \
    --chip bk7258 \
    --reset-mode rts \
    --start 0 \
    bk7258-flash.bin
```

Hardware validation read all 8 MiB with the download ROM CRC check enabled.
The upper 4 MiB contained data and was preserved; the tool does not infer that
flash outside the requested operation is disposable.

## Writing an executable image

Executable data is stored as 32 logical bytes followed by a two-byte,
big-endian CRC-16. The CRC uses polynomial `0x8005` and initial value `0xffff`.
The final logical block is padded with `0xff` before its CRC is calculated.

Use `--logical-start` for an ordinary, unpacked executable image. The tool maps
the logical XIP base `0x02000000` to physical flash offset zero and adds the CRC
bytes:

```sh
bk7231tools write_flash \
    --device /dev/ttyUSB0 \
    --chip bk7258 \
    --reset-mode rts \
    --logical-start 0x02000000 \
    --bootloader \
    --reboot \
    zephyr.bin
```

The `--bootloader` option is deliberately required for physical offsets below
`0x11000`. On a direct-boot BK7258 image this range contains the application,
not a separate first-stage loader, but an incorrect image can still leave the
device unbootable.

For an image that already contains the 32+2 CRC blocks, omit `--logical-start`
and pass its physical offset with `--start`. This is the existing raw physical
mode:

```sh
bk7231tools write_flash \
    --device /dev/ttyUSB0 \
    --chip bk7258 \
    --reset-mode rts \
    --start 0 \
    --bootloader \
    --reboot \
    zephyr.bk7258.bin
```

Only the 4 KiB sectors intersecting the input are erased. Each written sector
is checked with the download ROM CRC command. The original flash protection
bits are restored before an optional reboot.

The tool does not insert an image header, manifest, or `BK7236` marker. Those
formats are boot-chain policy rather than part of the serial transport or CRC
packing. A direct-boot image must provide any content required by its target
BootROM.

## Protocol evidence

The implementation uses the public, Apache-2.0 Beken SDK as the primary
protocol reference:

- `cp/components/bk_download/dl_protocol.h` defines the common and flash
  command identifiers.
- `cp/components/bk_download/dl_protocol.c` defines the short and long packet
  framing, inclusive CRC range, 4 KiB read/write, erase, baud-rate, register,
  flash-ID, and reboot requests.
- `tools/env_tools/bk_py_libs/bk_crc/bk_crc16.py` defines the 32-byte data plus
  two-byte CRC representation.
- `ap/include/soc/bk7258/reg_base.h` and
  `ap/middleware/soc/bk7258_ap/soc/sys_reg.h` place the BK7258 system version
  register at `0x44010004`.

The source is published in Beken's
[`bekencorp/bk_avdk_smp`](https://github.com/bekencorp/bk_avdk_smp) repository.
The references above were checked against SDK snapshot
`d6a9d1672534392e2f428751ba7c3b01920a2471`; the protocol and register files
carry Beken copyright notices and the Apache-2.0 license.
No code or protocol details were taken from unlicensed flashing tools or from
decompiling a vendor executable.

The following observations came from `bk7258-loader.pcapng`. The capture and
decoded transcript are validation artifacts and are deliberately not included
in this repository:

| Behavior | Capture frames | Public source cross-check |
| --- | --- | --- |
| Link-check request and successful response | 17-87 | `BkLinkCheckCmnd`, `BkLinkCheckResp`; SDK `dl_protocol.c` |
| BK7258 system-version register | 89-91 | SDK `reg_base.h`, `sys_reg.h` |
| JEDEC ID `c8 65 17` | 93-95 | `flash_read_id()` |
| Switch to 460800 baud | 101-107 | `BkSetBaudRateCmnd`; SDK `dl_protocol.c` |
| 4 KiB reads at physical offsets 0, 0x1000, and 0x2000 | 109-503 | `BkFlashRead4KCmnd`; SDK `dl_protocol.c` |
| Read and clear flash protection bits | 1021-1027 | `flash_unprotect()` |
| Erase only sectors 0, 0x1000, and 0x2000 | 1029-1039 | `BkFlashEraseBlockCmnd` |
| 4 KiB writes followed by ROM CRC checks | 1041-1079 | `flash_write_4k()`, `check_crc()` |
| Restore the original protection bits | 1081-1103 | `flash_restore_protection()` |
| Reboot request value `0xa5` | 1105-1109 | `BkRebootCmnd`; SDK `dl_protocol.c` |

CH342 control-transfer captures established the reset behavior. The loader
capture changes modem-control request A4 from `0x00ff` to `0x00bf` and back at
frames 9, 13, and 15. The successful open-tool capture
`open-probe-20261113-215254/bk7231tools-failed-link.pcapng` releases both lines
before opening the port and reproduces the RTS pulse at frames 21 and 37. The
pre-fix capture `open-probe-20261113-194547/bk7231tools-failed-link.pcapng`
instead held the other modem-control line active during frames 11-39 and never
linked. These traces are the basis for opening the serial port with DTR and RTS
released, then changing only RTS during the reset sequence.

Timeout and retry behavior remains the existing `bk7231tools` behavior:
`wait_for_link()` repeatedly sends the link check until `link_timeout` expires;
4 KiB reads and writes use `read_retries` and `write_retries`; and ROM CRC time
is included by `read_flash_range_crc()`. BK7258 adds no silent fallback path.

Compared with the older BK7231 profiles, BK7258 support therefore changes only
the following host-side behavior:

- force the FULL download-ROM command set instead of probing the legacy
  `0x00800000` SCTRL register;
- read the BK7258 system version register at `0x44010004`;
- determine physical flash capacity from the JEDEC ID;
- access physical offsets directly instead of using the BK7231N wraparound
  protection bypass;
- offer RTS-only reset and logical-image CRC packing.
